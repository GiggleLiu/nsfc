四个研究方向形成从理论到系统的完整链条：

\textbf{研究内容一：规约代价模型与路径优化。}建立规约编译的理论基础，将规约选择形式化为多项式代价图上的路径优化问题，研究最优路径的判定条件和搜索算法。

\textbf{研究内容二：LLM驱动的规模化规约发现。}提出测试先行的规约发现方法，利用大语言模型自动生成候选规约，结合ILP/SMT进行正确性验证，实现100+规约规则的规模化发现。

\textbf{研究内容三：问题规约编译器设计与实现。}构建编译器系统，集成规约知识库、路径规划器和后端代码生成器，实现从用户问题到量子硬件的端到端自动映射。

\textbf{研究内容四：量子优化平台实验验证。}在里德堡原子阵列和D-Wave量子退火机上验证编译器生成的规约，评估实际求解效果。

这四个方向相互支撑：理论研究（一）为编译器的路径选择提供算法基础；方法研究（二）为编译器提供规约知识库；系统研究（三）将理论和方法集成为可用工具；实验验证（四）检验系统的实际效果并提供反馈。


\section{研究内容一：规约代价模型与路径优化}

\subsection{研究目标}

传统编译器将高级语言转换为机器码时，需要在多种等价代码序列中选择代价最低的方案。问题规约编译器面临类似挑战：将用户问题"编译"到量子硬件时，需要在多条规约路径中自动选择最优方案。本研究的目标是建立规约路径优化的理论基础。

\subsection{代价模型}

与经典编译器的常数代价模型不同，规约代价是\textbf{问题规模的函数}。设问题$P$的规模由参数向量$\mathbf{n} = (n_1, n_2, \ldots)$描述，规约$r: P_i \to P_j$的代价可表示为多变量多项式：
\begin{equation}
	\text{cost}_r(\mathbf{n}) = \sum_{k} c_k \cdot n_1^{a_{k1}} n_2^{a_{k2}} \cdots
\end{equation}

例如，将$n$顶点、$m$边的图规约到三角晶格MIS，开销为$O(n^2 + m)$；3-SAT到MIS的规约，开销正比于子句数$m$。

\subsection{路径优化问题}

将规约空间建模为有向图$G = (V, E)$，其中顶点$V$为问题类型，边$E$为规约规则。给定源问题$P_s$和目标问题$P_t$，最优路径问题为：
\begin{equation}
	\pi^* = \arg\min_{\pi \in \text{Paths}(P_s, P_t)} \text{TotalCost}(\pi, \mathbf{n})
\end{equation}

\textbf{核心理论问题}：

\textbf{问题1：代价比较。}给定两条路径的代价多项式$f(\mathbf{n})$和$g(\mathbf{n})$，判定是否存在$\mathbf{n}_0$使得对所有$\mathbf{n} > \mathbf{n}_0$有$f(\mathbf{n}) < g(\mathbf{n})$。这涉及多变量多项式的渐进比较理论。

\textbf{问题2：Pareto最优。}当不存在全局最优路径时（即不同规模范围内最优路径不同），需要计算Pareto前沿——在各规模范围内分别最优的路径集合。

\textbf{问题3：高效搜索。}规约图可能包含100+节点和数百条边，需要开发高效的路径枚举和剪枝算法。

\subsection{技术路线}

\textbf{渐进分析框架：}借鉴计算复杂性理论中的渐进分析方法，建立多项式代价的偏序关系。对于单变量情形，利用主项比较；对于多变量情形，研究不同变量增长率假设下的比较策略。

\textbf{Pareto前沿计算：}开发增量式算法维护Pareto最优路径集合。当规约图更新时（新增规约规则），高效更新前沿而无需重新计算。

\textbf{启发式加速：}对于大规模规约图，开发基于问题结构的启发式剪枝策略，在保证解质量的前提下加速搜索。

\subsection{预期成果}

\textbf{理论成果：}建立规约路径优化的形式化框架，给出代价比较的可判定性条件，设计Pareto前沿的计算算法。

\textbf{算法实现：}开发路径优化算法库，作为编译器的核心模块，支持多种代价模型和搜索策略。


\section{研究内容二：LLM驱动的规模化规约发现}

\subsection{研究目标}

构建覆盖主流NP难问题的规约知识库需要发现和验证上百条规约规则。传统人工方法每条规约需要数周至数月，无法满足规模化需求。本研究提出\textbf{LLM驱动的测试先行开发方法}，将规约发现从"专家手工设计"转变为"人机协作的自动化流水线"。

\subsection{测试先行的规约发现}

借鉴软件工程中的测试驱动开发(TDD)理念，申请人提出规约发现的测试先行方法：

\textbf{步骤1：规范定义。}首先形式化定义规约的接口规范，包括：
\begin{itemize}
	\item 输入问题类型$P_s$和输出问题类型$P_t$的形式定义
	\item 规约映射$\phi: \text{Instance}(P_s) \to \text{Instance}(P_t)$的类型签名
	\item 解提取映射$\psi: \text{Sol}(P_t) \to \text{Sol}(P_s)$的类型签名
	\item 正确性性质的形式化陈述
\end{itemize}

\textbf{步骤2：测试套件构建。}在LLM生成规约之前，先构建验证正确性的测试套件：
\begin{itemize}
	\item 小规模穷举测试：对所有小规模实例验证解保持性和解可提取性
	\item 随机测试：生成大量随机实例进行统计验证
	\item 边界测试：针对特殊结构（空图、完全图、稀疏图等）的测试用例
\end{itemize}

\textbf{步骤3：LLM生成与迭代。}向大语言模型提供规范定义和测试套件，由LLM生成候选规约代码。测试失败时，将失败用例反馈给LLM进行迭代修正。

\textbf{步骤4：形式化验证。}对通过测试的规约，使用ILP或SMT求解器进行严格验证，确保正确性证明而非仅依赖测试覆盖。

\subsection{LLM提示工程}

有效的提示设计是LLM生成高质量规约的关键：

\textbf{知识编码：}将现有规约设计知识（如KSG编码\cite{Nguyen2023PRXQuantum}、TLSG编码\cite{Pan2025Triangular}）编码为结构化示例，包括设计动机、核心技巧、正确性论证。

\textbf{链式思维：}引导LLM逐步推理规约设计，从"需要编码什么约束"到"如何用目标问题结构表达"再到"如何保证正确性"。

\textbf{多模态输入：}对于几何约束（如晶格结构），探索将图形表示与文本描述结合的多模态提示方法。

\subsection{ILP/SMT验证框架}

申请人团队在三角晶格编码工作中\cite{Pan2025Triangular}首次将小工具验证形式化为整数线性规划(ILP)问题。本项目将扩展这一方法：

\textbf{ILP验证：}对于基于晶格结构的规约，构造ILP模型验证解保持性和解可提取性。决策变量为晶格位置的占用状态，约束条件编码独立集性质和逻辑线传递条件。

\textbf{SMT验证：}对于更一般的规约，使用SMT求解器（如Z3）编码一阶逻辑性质。SMT特别适合验证规约的组合性质和边界情形。

\textbf{反例驱动改进：}当验证失败时，求解器生成具体反例，这些反例可反馈给LLM指导规约设计的修正。

\subsection{进化式优化}

借鉴AlphaEvolve\cite{AlphaEvolve2025}的成功经验，对已验证规约进行进化优化：

\textbf{进化循环：}初始化（LLM生成种群）$\to$ 评估（ILP验证+代价计算）$\to$ 选择（保留高质量候选）$\to$ 变异（LLM生成变体）$\to$ 迭代。

\textbf{多目标优化：}同时优化多个指标，包括资源开销、质量因子（针对里德堡编码）、代码复杂度等。

\textbf{与AlphaEvolve的关键区别：}AlphaEvolve主要应用于数值优化，而本项目针对离散组合结构。关键创新在于将ILP/SMT求解器作为精确验证器嵌入进化循环，确保产出规约的可证明正确性。

\subsection{预期成果}

\textbf{规约知识库：}项目周期内完成100+规约规则的发现与验证，覆盖主流NP难问题（MIS、SAT、MAX-CUT、图着色、集合覆盖等）到量子优化原生问题（单位圆盘图MIS、QUBO）的映射。

\textbf{方法论贡献：}建立LLM驱动的测试先行规约发现方法论，为AI辅助算法发现提供新范式。

\textbf{开源工具：}发布规约发现工具链，支持多种LLM后端（GPT-4、Claude、Gemini等），集成ILP/SMT验证。


\section{研究内容三：问题规约编译器设计与实现}

\subsection{系统定位}

本项目的核心产出是一个\textbf{开源问题规约编译器}，为量子优化平台的使用者提供"一键映射"服务。用户只需指定：
\begin{itemize}
	\item \textbf{输入}：待求解的组合优化问题实例
	\item \textbf{目标}：量子硬件平台（里德堡原子阵列或D-Wave退火机）
\end{itemize}

编译器自动完成：问题识别 $\to$ 路径规划 $\to$ 逐步规约 $\to$ 硬件映射代码生成。

\subsection{系统架构}

编译器由四个核心模块组成：

\textbf{模块1：规约知识库。}存储研究内容二发现的100+规约规则，每条规则包含：
\begin{itemize}
	\item 规约映射$\phi$和解提取映射$\psi$的可执行实现
	\item 代价多项式的精确表达式
	\item 正确性验证的证据（ILP/SMT验证结果或形式化证明）
	\item 适用的硬件后端标注
\end{itemize}

\textbf{模块2：路径规划器。}基于研究内容一的理论，实现最优规约路径搜索：
\begin{itemize}
	\item 输入用户问题类型和目标平台
	\item 查询规约图，计算可行路径
	\item 根据问题规模参数，选择最优路径或呈现Pareto前沿供用户选择
\end{itemize}

\textbf{模块3：规约执行器。}沿选定路径逐步应用规约规则：
\begin{itemize}
	\item 管理中间问题实例的表示转换
	\item 记录每步规约的映射关系，以便最终解提取
	\item 支持中间结果的缓存和复用
\end{itemize}

\textbf{模块4：后端代码生成器。}针对目标平台生成可执行输入：
\begin{itemize}
	\item \textbf{里德堡后端}：生成原子坐标文件，兼容QuEra Bloqade等控制软件
	\item \textbf{D-Wave后端}：生成QUBO矩阵和嵌入方案，兼容Ocean SDK
\end{itemize}

\subsection{关键技术}

\textbf{问题识别：}自动识别用户输入问题的类型和结构参数。对于标准格式（如DIMACS CNF、DIMACS图格式），直接解析；对于自定义格式，提供问题描述DSL。

\textbf{增量编译：}当规约知识库更新时，支持增量重编译而无需从头计算，提高迭代开发效率。

\textbf{解的反向提取：}编译器不仅完成问题映射，还支持从硬件求解结果反向提取原问题的解。沿规约路径逆向应用解提取映射$\psi$。

\subsection{硬件后端优化}

\textbf{里德堡原子阵列：}
\begin{itemize}
	\item 支持多种晶格结构（正方、三角、蜂窝），自动选择最优编码
	\item 质量因子$Q$优化，最大化能量分离度
	\item 适配QuEra等公司的硬件参数（原子数上限、阻塞半径）
	\item 利用申请人开发的UnitDiskMapping.jl库进行编码优化
\end{itemize}

\textbf{D-Wave量子退火机：}
\begin{itemize}
	\item 针对Pegasus/Zephyr拓扑优化次嵌入
	\item 自动调优链强度参数$J_c$
	\item 集成D-Wave Ocean SDK的嵌入工具
\end{itemize}

\subsection{预期成果}

\textbf{编译器系统：}发布开源问题规约编译器，支持从主流NP难问题到里德堡和D-Wave平台的自动映射。

\textbf{用户接口：}提供命令行工具、Python API和Web界面，降低使用门槛。

\textbf{开发者接口：}支持自定义规约规则和后端扩展，便于社区贡献。


\section{研究内容四：量子优化平台实验验证}

\subsection{验证目标}

规约编译器的价值最终体现在实际量子硬件上的求解效果。本研究将与国际合作者开展实验验证，证明编译器生成的规约能高效求解实际问题。

\subsection{里德堡原子阵列验证}

\textbf{合作方：}Harvard/MIT Lukin团队、QuEra Computing Inc.

\textbf{验证平台：}QuEra Aquila量子计算机（256量子比特）及后续升级版本

\textbf{验证内容：}
\begin{itemize}
	\item \textbf{编码方案验证}：在真实硬件上验证三角晶格编码\cite{Pan2025Triangular}的性能，与KSG编码\cite{Nguyen2023PRXQuantum}对比
	\item \textbf{新发现规约测试}：测试LLM发现的新型小工具在实验中的表现
	\item \textbf{路径选择验证}：对于同一问题的不同规约路径，比较求解成功率和资源开销
\end{itemize}

\textbf{目标问题：}图着色、MAX-CUT、调度问题等经典NP难问题，规模从数十到数百顶点。

\subsection{D-Wave量子退火机验证}

\textbf{验证平台：}D-Wave Leap云服务（Advantage2系统，5000+量子比特）

\textbf{验证内容：}
\begin{itemize}
	\item \textbf{嵌入质量对比}：编译器生成的嵌入方案与Ocean SDK默认方法的比较
	\item \textbf{链强度优化效果}：自动调优的$J_c$参数对链断裂率的影响
	\item \textbf{大规模问题求解}：测试1000+变量的实际问题求解质量
\end{itemize}

\textbf{目标问题：}QUBO形式的组合优化问题，包括MAX-CUT、调度、投资组合优化等。

\subsection{验证指标}

\textbf{正确性：}求解结果是否为原问题的有效解，解的质量（与最优解的差距）。

\textbf{效率：}相比人工设计规约，编译器生成方案的资源开销是否更低。

\textbf{自动化程度：}从问题输入到硬件执行的端到端时间，用户干预程度。

\textbf{可扩展性：}随问题规模增大，编译时间和硬件资源的增长趋势。

\subsection{预期成果}

\textbf{实验数据：}在里德堡和D-Wave平台上的系统性实验结果，验证编译器的实用性。

\textbf{最佳实践：}总结不同问题类型和规模的最优规约策略，形成用户指南。

\textbf{反馈改进：}根据实验结果优化编译器的路径选择和后端代码生成。


\section{特色与创新点}

本项目的研究具有以下四个方面的特色与创新：

\textbf{创新点一：首次建立问题规约的代价模型理论。}将规约选择形式化为多项式代价图上的路径优化问题，研究代价比较的可判定性和Pareto最优路径的计算，为规约编译器提供理论基础。这一理论框架借鉴编译器优化的成熟思想，但针对规约代价的多项式特性进行了创新性扩展。

\textbf{创新点二：提出LLM驱动的测试先行规约发现方法。}将软件工程的TDD理念与大语言模型结合，实现规约的规模化发现。关键创新在于将ILP/SMT求解器作为精确验证器嵌入生成循环，确保产出规约的可证明正确性，而非仅依赖测试覆盖。

\textbf{创新点三：构建首个问题规约编译器系统。}让用户像使用传统编译器一样使用量子优化平台——只需描述问题，无需了解硬件细节。编译器集成规约知识库、路径规划和硬件后端，实现端到端自动化。

\textbf{创新点四：开源规约知识库推动社区发展。}扩展problem-reductions库\cite{ProblemReductions2025}至100+规约规则，每条规约配备代价多项式、正确性证明和硬件适配信息。这将显著降低量子优化平台的使用门槛，促进技术普及。
