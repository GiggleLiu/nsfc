本项目围绕"LLM辅助面向物理计算平台的问题规约自动发现与验证"这一核心目标，构建包含三个紧密关联的研究方向的系统性框架，如图\ref{fig:framework}所示。

三个研究方向形成"发现$\rightarrow$验证$\rightarrow$优化$\rightarrow$实验验证$\rightarrow$反馈"的闭环：

\textbf{研究内容一：LLM辅助规约小工具自动发现。}利用大语言模型的代码生成与推理能力，结合整数线性规划验证，在给定源问题、目标问题和约束条件下自动生成候选规约方案。采用AlphaEvolve式的进化优化策略，通过"LLM生成$\rightarrow$ILP验证$\rightarrow$优胜选择$\rightarrow$变异进化"的迭代过程，高效探索规约设计空间。

\textbf{研究内容二：规约正确性形式化验证。}为保证规约的可靠性，研究LLM辅助的形式化证明生成技术。将规约正确性性质（解保持性与解可提取性）转化为可机器验证的形式规范，与Lean4/mathlib定理证明器集成，并利用SMT求解器处理小规模实例验证。

\textbf{研究内容三：硬件感知规约优化。}针对里德堡原子阵列、D-Wave量子退火机、张量网络三类典型物理计算平台，研究在满足正确性前提下最小化硬件资源开销、最大化解质量的优化策略。开发平台特定的优化模块，并与合作者开展实验验证。

这三个研究方向相互支撑：研究内容一提供候选规约，研究内容二验证其正确性，研究内容三优化其硬件效率；同时，硬件实验的反馈将指导规约发现的方向，验证结果将筛选出高质量规约进入优化流程。这一闭环机制确保产出的规约既有理论保证，又有实用价值。


\section{研究内容一：LLM辅助规约小工具自动发现}

\subsection{问题定义}

问题规约的核心在于设计\textbf{小工具(gadget)}——用目标问题的基本结构编码源问题的约束条件。以里德堡原子阵列为例，将任意图的最大独立集(MIS)问题映射到单位圆盘图需要设计交叉小工具(crossing gadget)来处理边的交叉\cite{Nguyen2023PRXQuantum,Pan2025Triangular}。

形式化地，小工具设计问题的输入包括：
\begin{itemize}[left=2em]
	\item \textbf{源问题}$P_s$：需要求解的原始组合优化问题（如任意图MIS）
	\item \textbf{目标问题}$P_t$：物理计算平台原生支持的问题（如单位圆盘图MIS）
	\item \textbf{约束条件}$\mathcal{C}$：硬件施加的几何、拓扑或资源限制（如三角晶格结构）
\end{itemize}

输出为一个\textbf{最小开销小工具}$G^*$，满足：
\begin{equation}
	G^* = \arg\min_{G \in \mathcal{G}} \text{cost}(G) \quad \text{s.t.} \quad \text{correct}(G, P_s, P_t) \wedge \text{satisfy}(G, \mathcal{C})
\end{equation}
其中$\mathcal{G}$为候选小工具空间，$\text{cost}(G)$衡量资源开销（如顶点数），$\text{correct}$验证规约正确性，$\text{satisfy}$检查约束满足性。

以三角晶格编码为例\cite{Pan2025Triangular}，一个交叉小工具需满足：两条穿过小工具的"逻辑线"保持独立，即一条线上选中顶点不影响另一条线的可选状态。这需要在晶格约束下精心设计顶点位置和权重分配。

\subsection{技术路线}

\subsubsection{LLM候选生成}

利用大语言模型的代码生成与推理能力自动生成候选小工具。关键技术包括：

\textbf{知识编码与提示工程。}将问题规约的领域知识编码为LLM可理解的形式：
\begin{itemize}[left=2em]
	\item 构建包含已知小工具设计的知识库，提供结构化的设计模式描述
	\item 设计针对规约发现的专用提示模板，明确指定输入输出格式
	\item 利用链式思维(Chain-of-Thought)引导LLM逐步推理小工具的设计逻辑
\end{itemize}

\textbf{少样本学习。}利用现有高质量小工具作为示例：
\begin{itemize}[left=2em]
	\item 从KSG编码\cite{Nguyen2023PRXQuantum}和TLSG编码\cite{Pan2025Triangular}中提取典型设计模式
	\item 构建"问题描述$\rightarrow$小工具设计$\rightarrow$正确性论证"的示例链
	\item 通过上下文学习让LLM理解小工具设计的核心原则
\end{itemize}

\textbf{多模态输入。}结合图形化表示增强LLM理解：
\begin{itemize}[left=2em]
	\item 将晶格结构、小工具图形以结构化文本或图像形式输入
	\item 利用视觉语言模型理解几何约束
	\item 支持从草图到代码的转换
\end{itemize}

\subsubsection{整数线性规划验证}

申请人团队在三角晶格编码工作中\cite{Pan2025Triangular}首次将小工具验证形式化为整数线性规划(ILP)问题。本项目将扩展这一方法：

\textbf{ILP形式化框架。}给定候选小工具$G$，构造如下ILP：
\begin{itemize}[left=2em]
	\item \textbf{决策变量}：每个晶格位置的顶点占用状态$x_i \in \{0,1\}$
	\item \textbf{独立集约束}：相邻顶点不能同时选中，$x_i + x_j \leq 1$, $\forall (i,j) \in E$
	\item \textbf{逻辑线约束}：编码源问题约束的传递性条件
	\item \textbf{目标函数}：最小化顶点总数或最大化质量因子
\end{itemize}

\textbf{正确性验证。}通过求解ILP检验小工具的关键性质：
\begin{itemize}[left=2em]
	\item \textbf{解保持性}：源问题的任意解都对应目标问题的有效解
	\item \textbf{解可提取性}：从目标问题的最优解可唯一确定源问题的解
	\item \textbf{开销界}：验证资源开销在可接受范围内
\end{itemize}

这一ILP框架已在12顶点交叉小工具搜索中验证了有效性，本项目将扩展至更大规模和更多类型的小工具。

\subsubsection{进化式优化}

借鉴AlphaEvolve的成功经验\cite{AlphaEvolve2025}，采用LLM驱动的进化优化策略：

\textbf{进化循环设计：}
\begin{enumerate}[left=2em]
	\item \textbf{初始化}：LLM基于知识库生成初始候选小工具种群
	\item \textbf{评估}：使用ILP验证每个候选的正确性，计算适应度（开销、质量因子）
	\item \textbf{选择}：保留通过验证且适应度高的候选
	\item \textbf{变异}：LLM基于当前最优候选生成变异版本
	\item \textbf{迭代}：重复评估-选择-变异直到收敛
\end{enumerate}

\textbf{关键优化策略：}
\begin{itemize}[left=2em]
	\item \textbf{多目标优化}：同时优化多个指标（顶点数、质量因子、对称性）
	\item \textbf{约束松弛}：对难以满足的硬约束采用渐进式松弛策略
	\item \textbf{经验回放}：维护历史最优解库，避免重复探索
	\item \textbf{局部搜索}：对有潜力的候选进行精细化局部优化
\end{itemize}

\textbf{与AlphaEvolve的区别与创新：}AlphaEvolve主要应用于数学问题的数值优化，而本项目针对的是离散的组合结构设计。关键创新在于将ILP求解器作为精确验证器嵌入进化循环，确保产出的小工具具有可证明的正确性，而非仅依赖经验测试。

\subsection{预期成果}

\textbf{LLM-ILP混合系统：}开发一套完整的规约发现工具链，集成LLM候选生成、ILP正确性验证和进化优化三个模块。该系统将作为开源软件发布，支持多种LLM后端（GPT-4、Claude、Gemini等）。

\textbf{新发现的小工具：}预期在项目周期内发现\textbf{5-10种新型高质量小工具}，覆盖：
\begin{itemize}[left=2em]
	\item 三角晶格上的多种交叉小工具变体（不同开销-质量权衡）
	\item 正方晶格上的改进KSG编码组件
	\item D-Wave Pegasus/Zephyr拓扑上的嵌入小工具
	\item 张量网络收缩的优化分解模式
\end{itemize}

\textbf{效率提升：}将小工具设计时间从人工的\textbf{数周至数月缩短为数小时至数天}。对于规模适中的小工具（$\leq 20$顶点），实现全自动发现；对于更大规模，提供人机协作模式。


\section{研究内容二：规约正确性形式化验证}

\subsection{挑战与目标}

问题规约的正确性是其实用价值的根本保证。一个正确的规约需要满足两个核心性质：

\textbf{解保持性(Soundness)：}源问题$P_s$的任意可行解$s$都能通过规约映射$\phi$转化为目标问题$P_t$的可行解$\phi(s)$，且目标函数值保持相应关系。形式化地：
\begin{equation}
	\forall s \in \text{Sol}(P_s): \phi(s) \in \text{Sol}(P_t) \wedge f_t(\phi(s)) = g(f_s(s))
\end{equation}
其中$f_s, f_t$分别为源问题和目标问题的目标函数，$g$为值映射函数。

\textbf{解可提取性(Completeness)：}从目标问题$P_t$的最优解$t^*$可以唯一确定源问题$P_s$的最优解$\psi(t^*)$。形式化地：
\begin{equation}
	\forall t^* \in \text{Opt}(P_t): \psi(t^*) \in \text{Opt}(P_s)
\end{equation}
其中$\psi$为解提取映射，$\text{Opt}$表示最优解集合。

当前规约正确性验证面临的主要挑战包括：
\begin{itemize}[left=2em]
	\item 人工证明容易出错，且难以复用和扩展
	\item 缺乏统一的形式化框架和自动化工具支持
	\item LLM生成的规约尤其需要可靠的验证机制
\end{itemize}

本研究的目标是建立一套\textbf{可扩展、可复用、机器可验证}的规约正确性验证框架。

\subsection{技术路线}

\subsubsection{LLM辅助证明草稿生成}

利用LLM的数学推理能力辅助生成正确性证明的初步框架：

\textbf{证明模板库构建：}
\begin{itemize}[left=2em]
	\item 分析经典NP完全性证明\cite{Lucas2014Frontiers}的结构模式
	\item 提取常用证明技巧：归纳、反证、构造性证明等
	\item 针对不同类型规约设计专用证明模板
\end{itemize}

\textbf{LLM证明生成：}
\begin{itemize}[left=2em]
	\item 输入规约定义和目标性质，LLM生成自然语言证明草稿
	\item 利用链式思维逐步展开证明论证
	\item 生成多个候选证明路径供后续验证
\end{itemize}

\textbf{证明精炼迭代：}
\begin{itemize}[left=2em]
	\item 根据验证器反馈修正证明中的错误或缺口
	\item 逐步细化证明细节直至通过形式化验证
	\item 记录成功证明策略以指导后续生成
\end{itemize}

\subsubsection{与Lean4/mathlib集成}

将LLM生成的证明草稿转化为机器可验证的形式化证明：

\textbf{Lean4规约语言设计：}
\begin{itemize}[left=2em]
	\item 在Lean4中定义问题规约的基本概念：问题、解、规约映射
	\item 形式化解保持性和解可提取性的定义
	\item 利用mathlib库中的组合学和图论基础设施
\end{itemize}

\textbf{证明翻译器开发：}
\begin{itemize}[left=2em]
	\item 构建从自然语言证明到Lean4策略(tactic)的翻译规则
	\item 利用LLM作为翻译引擎，将证明步骤映射到Lean4命令
	\item 开发交互式证明辅助工具，支持人工介入关键步骤
\end{itemize}

\textbf{证明自动化：}
\begin{itemize}[left=2em]
	\item 对于常见证明模式，开发专用Lean4策略自动完成
	\item 集成自动定理证明器(如aesop)处理例行推理
	\item 构建规约证明的策略库(tactic library)
\end{itemize}

\subsubsection{SMT求解器验证}

对于小规模实例，使用SMT求解器(如Z3)进行穷举验证：

\textbf{SMT编码：}
\begin{itemize}[left=2em]
	\item 将规约正确性性质编码为一阶逻辑公式
	\item 通过枚举所有可能输入验证解保持性
	\item 验证解提取映射的唯一性和正确性
\end{itemize}

\textbf{适用场景：}
\begin{itemize}[left=2em]
	\item 小工具规模较小（$\leq 15$顶点）时进行完全验证
	\item 作为形式化证明的补充，增强可信度
	\item 快速筛选候选规约，过滤明显错误的设计
\end{itemize}

\textbf{反例生成：}
\begin{itemize}[left=2em]
	\item 当验证失败时，SMT求解器可生成具体反例
	\item 反例用于指导规约设计的修正
	\item 构建反例库辅助LLM学习失败模式
\end{itemize}

\subsection{预期成果}

\textbf{验证框架：}开发完整的规约正确性验证工具链，包括：

\subsection{里德堡原子阵列优化}

里德堡原子阵列通过里德堡阻塞效应原生求解单位圆盘图上的MIS问题\cite{Ebadi2022Science}。优化目标包括：

\textbf{原子数最小化：}
\begin{itemize}[left=2em]
	\item 减少编码所需的总原子数，降低实验复杂度
	\item 探索不同晶格结构（正方、三角、蜂窝）的开销特性
	\item 针对特定问题实例寻找紧凑编码
\end{itemize}

\textbf{质量因子Q最大化：}
\begin{itemize}[left=2em]
	\item 质量因子$Q$定义为最小可区分距离与阻塞半径之比
	\item 能量分离度正比于$Q^6$，直接影响求解成功率
	\item TLSG编码\cite{Pan2025Triangular}实现$Q=\sqrt{3}$，本项目目标是进一步提升
\end{itemize}

\textbf{针对特定硬件的适配：}
\begin{itemize}[left=2em]
	\item 适配QuEra等公司的具体硬件参数（原子数上限、阻塞半径范围）
	\item 考虑原子位置控制精度的影响
	\item 针对退火时间约束优化编码设计
\end{itemize}

\textbf{技术方案：}结合研究内容一的LLM-ILP混合框架，将Q因子最大化作为多目标优化的指标之一。利用申请人团队开发的UnitDiskMapping.jl库\cite{UnitDiskMapping2023}进行快速编码评估。

\subsection{D-Wave嵌入优化}

D-Wave量子退火机采用固定的Pegasus/Zephyr拓扑结构，将任意QUBO问题映射到该拓扑需要次嵌入(minor embedding)\cite{DWave2025Science}。优化目标包括：

\textbf{嵌入开销最小化：}
\begin{itemize}[left=2em]
	\item 每个逻辑变量映射到的物理量子比特"链"越短越好
	\item 最小化总物理量子比特使用数
	\item 平衡链长度，避免极长链引入的误差
\end{itemize}

\textbf{链强度优化：}
\begin{itemize}[left=2em]
	\item 链内量子比特需保持一致状态，由链强度$J_c$控制
	\item $J_c$过小导致链断裂，过大压缩问题能量尺度
	\item 针对不同问题结构自动调优$J_c$
\end{itemize}

\textbf{拓扑感知规约：}
\begin{itemize}[left=2em]
	\item 在QUBO规约阶段就考虑目标拓扑的连接模式
	\item 优先使用Pegasus/Zephyr中高连接度的量子比特
	\item 针对常见问题结构预计算优化嵌入模板
\end{itemize}

\textbf{技术方案：}利用D-Wave Ocean SDK的嵌入工具作为基础，开发LLM辅助的规约优化层。通过强化学习训练嵌入策略网络，实现比启发式方法更优的嵌入质量。

\subsection{张量网络收缩优化}

张量网络方法\cite{Liu2021PRL,Liu2023SIAM}的计算复杂度由收缩顺序决定，核心指标是树宽。优化目标包括：

\textbf{树宽最小化：}
\begin{itemize}[left=2em]
	\item 收缩复杂度为$O(\exp(\text{tw}))$，树宽每降低1可带来指数级加速
	\item 利用问题结构（如稀疏性、对称性）寻找低树宽分解
	\item 探索近似算法与精确算法的权衡
\end{itemize}

\textbf{收缩顺序优化：}
\begin{itemize}[left=2em]
	\item 给定树分解，寻找最优的张量收缩顺序
	\item 考虑内存使用与计算时间的平衡
	\item 针对GPU并行性优化收缩策略
\end{itemize}

\textbf{规约引导分解：}
\begin{itemize}[left=2em]
	\item 在问题规约阶段引入结构约束，使目标问题具有低树宽
	\item 牺牲少量问题规模换取显著的树宽降低
	\item 针对特定问题类别设计专用规约-分解联合优化
\end{itemize}

\textbf{技术方案：}扩展申请人团队开发的GenericTensorNetworks.jl库\cite{GenericTensorNetworks2023}，集成LLM辅助的收缩顺序搜索。利用强化学习训练收缩策略，结合传统的最小度算法和分离器方法。

\section{特色与创新点}

本项目的研究具有以下四个方面的特色与创新：

\textbf{创新点一：首次系统研究LLM辅助问题规约自动发现。}
\begin{itemize}[left=2em]
	\item 将AlphaEvolve范式\cite{AlphaEvolve2025}创新性地应用于组合问题规约领域
	\item 提出LLM生成与ILP验证相结合的混合框架，兼具生成能力与可证明正确性
	\item 建立从知识编码、候选生成到进化优化的完整方法论
	\item 填补LLM在计算复杂性理论应用方面的研究空白
\end{itemize}

\textbf{创新点二：形式化验证保证规约正确性。}
\begin{itemize}[left=2em]
	\item 首次将问题规约的正确性性质形式化为可机器验证的规范
	\item 开发LLM辅助的证明生成技术，降低形式化验证门槛
	\item 实现自然语言证明到Lean4形式化证明的自动翻译
	\item 建立规约正确性证明的可复用库，促进知识积累
\end{itemize}

\textbf{创新点三：硬件感知的端到端规约优化框架。}
\begin{itemize}[left=2em]
	\item 突破传统规约研究只关注渐进复杂度的局限
	\item 针对里德堡、D-Wave、张量网络三类平台建立专用优化方法
	\item 实现从问题定义到硬件执行的端到端自动化
	\item 通过硬件实验验证规约的实际效果
\end{itemize}

\textbf{创新点四：开源工具链推动社区发展。}
\begin{itemize}[left=2em]
	\item 扩展problem-reductions库\cite{ProblemReductions2025}，实现100+种问题和规约
	\item 每条规约配备形式化验证和硬件适配信息
	\item 降低物理计算平台的使用门槛，促进技术普及
	\item 建立开放的规约知识库，支持社区贡献和持续扩展
\end{itemize}
